# 一人公司 AI 自动化交付模板包：线索、项目简报、QA 验收

检索日期：2026-06-17

## 为什么先补模板

一人公司做 AI 自动化服务时，最大的交付风险通常不是“不会接 API”，而是输入不稳定、范围不清、审批点缺失、验收口径模糊。模板的目标是把每个项目都压成三份可复用资产：

| 阶段 | 文件 | 解决的问题 | 下游用途 |
| --- | --- | --- | --- |
| 线索进入 | `templates/lead.json` | 线索字段、授权证据、风险标签不统一 | CRM 入库、AI 资格判断、首次跟进 |
| 诊断成交 | `templates/project_brief.md` | 客户目标、数据源、范围、指标不清 | 报价、合同附件、实施看板 |
| 交付验收 | `templates/qa_report.md` | “测过了”不可复测 | 客户验收、上线决策、复盘案例 |

## 推荐接入工作链

| 步骤 | 自动化动作 | AI 动作 | 人工审批点 | 输出 |
| --- | --- | --- | --- | --- |
| 1. 表单提交 | 表单写入线索表 | 按 `lead.json` 补全结构化字段 | 含敏感数据或授权不明时人工确认 | 新线索记录 |
| 2. 资格判断 | 根据行业、预算、周期、风险标签打分 | 生成 fit score、下一步问题和跟进草稿 | 分数边界、法律税务敏感、预算异常时人工确认 | 线索分级 |
| 3. 诊断会后 | 会议纪要和线索表合并 | 生成 `project_brief.md` 初稿 | 报价、承诺、上线周期必须人工确认 | 项目简报 |
| 4. 搭建测试 | 自动跑正常/异常用例 | 归纳失败原因和修复建议 | 生产写入、外发消息、删除数据前必须审批 | QA 记录 |
| 5. 客户验收 | 发送验收材料 | 生成客户可读摘要 | 客户可见材料发送前审批 | `qa_report.md` |
| 6. 复盘变现 | 统计节省时间、响应速度、错误率 | 生成案例草稿和续费建议 | 对外案例发布前审批 | 案例/续费包 |

## `lead.json` 字段使用规则

| 字段 | 必填 | 规则 | 异常处理 |
| --- | --- | --- | --- |
| `source.consent_evidence` | 是 | 记录客户同意或来源证据 | 缺失时只能进入人工跟进，不能自动营销外发 |
| `problem_statement.weekly_hours_spent` | 是 | 用数字估算节省空间 | 不确定时填 0，并在诊断会确认 |
| `qualification.fit_score_0_100` | 是 | 70 以上优先诊断，40-69 培育，40 以下暂缓 | 分数由 AI 生成后需保留原因 |
| `risk_review.personal_information_involved` | 是 | 只要涉及联系人、客户名单、聊天记录就标记 | 触发数据最小化和脱敏 |
| `risk_review.live_system_write_access` | 是 | CRM、订单、财务、权限系统写入都算 | 必须有人审和回滚方案 |
| `next_action.message_draft` | 否 | AI 只生成草稿 | 客户可见消息不得自动发送 |

## 线索评分建议

| 维度 | 分值 | 高分标准 |
| --- | ---: | --- |
| 痛点明确 | 20 | 能说清流程、频次、耗时和错误 |
| ROI 可量化 | 20 | 能用时间、转化率、响应速度或返工率验收 |
| 数据可获得 | 15 | 表格、CRM、邮件、文档等数据源可导出或接入 |
| 决策链短 | 15 | 一次诊断会能接触负责人或决策人 |
| 风险可控 | 15 | 不涉及高风险专业判断或不可控外发 |
| 预算匹配 | 15 | 预算覆盖诊断、搭建和至少一个月维护 |

建议阈值：

| 分数 | 处理 |
| ---: | --- |
| 80-100 | 48 小时内安排诊断会 |
| 60-79 | 发 3 个补充问题，确认后再报价 |
| 40-59 | 进入内容培育或低价诊断 |
| 0-39 | 暂不承接，记录原因 |

## 项目简报的人工审批规则

`project_brief.md` 生成后，不要直接作为报价发给客户。至少检查：

| 检查项 | 不通过表现 | 处理 |
| --- | --- | --- |
| 范围 | 写了“全自动解决所有获客问题”等泛化承诺 | 改成具体流程和交付物 |
| 指标 | 只有“提升效率”没有当前值/目标值 | 补当前耗时、错误率、响应时间 |
| 数据 | 未区分可用、脱敏、不可用数据 | 回访客户确认授权 |
| 审批 | 外发消息、报价、删除、写入没有人审 | 加审批节点和驳回路径 |
| 维护 | 未写账号、密钥、异常提醒归属 | 写清客户/交付方责任边界 |

## QA 报告的上线门槛

| 条件 | 上线结论 |
| --- | --- |
| 有 P0 问题 | 禁止上线 |
| 有 P1 问题 | 修复并复测后上线 |
| 只有 P2 且有人工绕行办法 | 可有条件上线，写入观察期 |
| 只有 P3 | 可上线，进入下次迭代 |

最低复测组合：

| 类型 | 最少用例 |
| --- | --- |
| 正常路径 | 1 个完整端到端样例 |
| 缺字段 | 1 个缺联系方式或缺预算样例 |
| 重复记录 | 1 个同公司/同手机号样例 |
| 高风险审批 | 1 个客户可见外发样例 |
| 工具失败 | 1 个 API/表格写入失败样例 |
| 敏感数据 | 1 个含个人信息或商业秘密样例 |

## 工具配置注意点

| 平台/能力 | 适合任务 | 关键配置 |
| --- | --- | --- |
| OpenAI Responses API | 单次模型调用、工具调用、文件/网页等工具组合 | 工具权限最小化，保留输入输出和评估样例 |
| OpenAI Agents SDK | 多步骤编排、多 Agent 协作、状态和审批由应用控制 | 把审批、工具执行、状态存储放在应用层 |
| n8n AI Agent | 自托管、可视化流程、需要连接多系统 | 对高风险工具启用 human-in-the-loop |
| Make AI Agents | 低代码编排、销售外联、工单分流、市场研究 | 只交给“实习生级别可信”的任务，避免高风险决策 |
| Zapier Human in the Loop | Zap 中暂停等待审批 | 外发、改数据、删数据前使用 Request Approval |

## 变现路径

| 产品 | 交付物 | 定价逻辑 | 续费点 |
| --- | --- | --- | --- |
| 线索诊断包 | `lead.json` 字段设计、线索评分规则、3 条跟进话术 | 低价入口，按一次诊断收费 | 转搭建包 |
| 首条工作链搭建 | 表单、数据表、AI 分类、人工审批、QA 报告 | 按流程复杂度和接入系统数收费 | 月度维护 |
| 托管优化包 | 每月 QA、异常修复、提示词优化、案例复盘 | 按月收费 | 新流程扩展 |
| 行业模板包 | 某行业线索字段、项目简报、QA 用例 | 按模板授权或培训收费 | 社群/课程 |
