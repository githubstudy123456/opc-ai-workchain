# 一人公司 AI Agent 工作链 SOP：从获客到交付与风控

> 检索日期：2026-06-16。本文中的 OPC 指 One-Person Company / 一人公司，不涉及 OPC UA 或 OPC Classic。

## 适用场景

一人公司可以把“获客、资格判断、需求澄清、方案报价、交付、复盘、续费”拆成可审计的 AI 工作链。核心原则不是完全无人化，而是把高频、低风险、可验证的动作自动化，把报价、承诺、付款、合同、税务、对外发送等动作设置人工审批点。

## 端到端工作链

| 阶段 | 触发输入 | AI/自动化动作 | 工具配置 | 人工审批点 | 输出 | 验收标准 |
|---|---|---|---|---|---|---|
| 1. 线索采集 | 官网表单、私信、邮件、社群报名表 | 标准化联系人、公司、预算、痛点、来源渠道 | 表单 + CRM/表格 + 自动化平台 Webhook | 不需要，除非包含敏感个人信息 | `lead.json` | 必填字段完整率 >= 95%，重复线索可合并 |
| 2. 资格判断 | `lead.json` | 按 ICP 打分，识别行业、预算、时效、合规风险 | LLM 分类 + 规则阈值 | 分数 60-75 或高风险行业需人工复核 | `lead_score`、下一步建议 | 低分线索不进入深度咨询，高分线索 24 小时内响应 |
| 3. 需求澄清 | 合格线索 | 生成 5-8 个澄清问题，按业务目标、现有工具、数据权限拆分 | 邮件草稿/IM 草稿，不自动发送 | 对外发送前人工确认 | 澄清问题清单 | 问题具体、可回答、避免泛泛问卷 |
| 4. 方案与报价 | 澄清回复、历史案例、交付包模板 | 生成方案范围、里程碑、边界、报价区间 | 文档模板 + 知识库检索 | 必须人工确认报价、交付承诺、法律条款 | 方案草稿、报价草稿 | 明确“不包含事项”、验收口径、变更收费 |
| 5. 合同与收款 | 客户确认方案 | 生成合同变量清单、发票信息核对清单、付款提醒 | 合同模板 + 电子签 + 支付/银行提醒 | 必须人工确认合同、收款账户、发票类型 | 合同待签版、收款任务 | 合同与报价一致，未收预付款不启动高成本交付 |
| 6. 交付执行 | 已签约项目 | 拆分任务、拉取素材、生成初稿、检查缺失项 | 项目管理工具 + 文件夹模板 + Agent runner | 客户可见交付物发布前人工确认 | 初稿、检查报告 | 每个交付物有版本号、来源、变更记录 |
| 7. 质量验收 | 初稿/成品 | 自动跑清单：事实、链接、格式、权限、敏感信息、可复现步骤 | Lint/脚本/LLM reviewer | 高风险内容、生产环境动作必须确认 | QA 报告、修订建议 | P0/P1 问题清零，客户验收标准逐项对应 |
| 8. 复盘与续费 | 项目完成、客户反馈 | 归档材料，生成复盘、案例摘要、二次销售机会 | CRM + 知识库 + 自动提醒 | 对外案例发布前需客户授权 | 复盘记录、续费建议 | 7 日内完成复盘，形成可复用模板 |

## Agent 设计规范

| Agent | 职责 | 允许工具 | 禁止动作 | 失败处理 |
|---|---|---|---|---|
| 线索分拣 Agent | 清洗线索、ICP 评分、去重 | CRM 查询、表格读写、邮件读取 | 删除客户记录、直接拒绝客户 | 打低置信度标签并转人工 |
| 研究 Agent | 客户行业、竞品、公开资料研究 | Web 搜索、文件检索、引用整理 | 编造来源、访问未授权数据 | 每条关键结论附来源链接 |
| 方案 Agent | 生成交付范围、里程碑、报价依据 | 模板库、历史项目库、计算器 | 自动发送报价、承诺法律/税务结论 | 输出“需人工确认”字段 |
| 交付 Agent | 生成初稿、脚本、流程、清单 | 文件读写、代码/低代码平台、知识库 | 生产环境改动、付款、合同签署 | 生成变更单和回滚建议 |
| 审核 Agent | 对交付物做事实、隐私、合规检查 | 文档读取、规则库、链接检查 | 覆盖原始文件、替代专业意见 | 输出 P0/P1/P2 风险分级 |

建议把工具调用拆成 `search -> resolve -> preview -> execute -> verify -> recover` 六步：先搜索候选对象，再解析唯一对象，预览影响，执行动作，验证结果，最后在失败时给恢复路径。这样比直接让 Agent 调 CRUD API 更适合一人公司控制风险。

## 提示词模板

### 线索资格判断

```text
你是一人公司获客助理。请基于以下线索判断是否进入深度咨询。

输入：
- 线索来源：{{source}}
- 客户描述：{{message}}
- 预算：{{budget}}
- 期望交付时间：{{deadline}}
- 行业：{{industry}}

请输出 JSON：
{
  "icp_score": 0-100,
  "fit_reason": "最多 80 字",
  "risk_flags": ["预算不足|时效不合理|合规敏感|需求不清|无决策权"],
  "next_action": "reject|nurture|ask_clarifying_questions|book_call",
  "questions": ["最多 6 个澄清问题"]
}

约束：
- 不要承诺结果。
- 涉及法律、税务、医疗、金融投资结论时标记合规敏感。
- 分数 60-75 必须建议人工复核。
```

### 交付物审核

```text
你是一人公司交付审核员。请检查交付物是否可以发给客户。

输入：
- 项目目标：{{goal}}
- 验收标准：{{acceptance_criteria}}
- 交付物：{{deliverable}}
- 来源链接：{{sources}}

请按 P0/P1/P2 输出问题：
- P0：可能造成客户损失、泄密、违法违规、生产事故。
- P1：影响验收或关键事实错误。
- P2：表达、格式、可维护性问题。

最后输出：
1. 是否可发送：yes/no
2. 必须修改项
3. 建议修改项
4. 需要人工确认的问题
```

## 人工审批清单

| 审批事项 | 为什么必须人工确认 | 证据材料 |
|---|---|---|
| 对外报价 | 防止 AI 报错价格、范围或付款条件 | 报价单、成本估算、历史报价 |
| 合同条款 | 合同风险不能由通用模型替代专业判断 | 合同版本、变更记录、客户确认 |
| 发票与税务口径 | 税务政策有适用条件与地区差异 | 税务机关链接、会计确认记录 |
| 客户数据导入 | 涉及隐私、权限、保密义务 | 数据清单、授权记录、脱敏策略 |
| 生产环境操作 | 防止不可逆变更 | 操作预览、备份、回滚方案 |
| 对外发布案例 | 需要客户授权，避免泄露商业信息 | 授权邮件、脱敏稿 |

## 异常处理

| 异常 | 自动处理 | 升级条件 | 人工动作 |
|---|---|---|---|
| 工具 API 失败 | 重试 2 次，记录请求 ID | 仍失败或影响交付期限 | 切换手工流程并通知客户 |
| Agent 低置信度 | 输出缺失字段和原因 | 置信度 < 0.75 | 人工补充上下文或终止自动化 |
| 来源不可访问 | 换用官方/权威来源二次检索 | 关键事实无来源 | 删除该事实或标注未确认 |
| 客户需求变更 | 生成变更影响评估 | 影响价格、周期、范围 | 发变更单并重新确认 |
| 涉及敏感行业 | 标记合规敏感 | 法律、税务、医疗、金融、招聘歧视等 | 引入专业人士或拒绝交付 |

## 变现路径

| 产品化服务 | 目标客户 | 交付周期 | 定价方式 | 可复用资产 |
|---|---|---|---|---|
| 获客到 CRM 自动化 | 咨询、培训、B2B 服务一人公司 | 3-7 天 | 固定价 + 维护费 | 表单、评分规则、CRM 字段 |
| AI 客服知识库 | 小微电商、SaaS、课程社群 | 5-10 天 | 设置费 + 月费 | FAQ 模板、检索评测集 |
| 内容生产流水线 | 自媒体、知识付费、品牌主理人 | 3-5 天 | 套餐价 | 选题库、审稿清单、发布日历 |
| 交付 SOP 自动化 | 设计、开发、咨询工作室 | 7-14 天 | 项目制 + 复盘包 | 项目模板、验收清单、复盘模板 |
| 合规风控体检 | 已在使用 AI/自动化的小团队 | 2-5 天 | 诊断报告价 | 风险矩阵、审批点清单 |

- Zapier 官方 AI automation 文章用于确认低代码/无代码自动化与 AI 结合的典型业务场景；检索日期：2026-06-16。来源：https://zapier.com/blog/ai-automation/
- AutomationBench 论文指出真实业务自动化需要跨应用协同、API 发现与策略遵守，且前沿模型在该基准上仍低于 10% 成功率；因此本文把人工审批、可验证状态和失败恢复作为默认设计。检索日期：2026-06-16。来源：https://arxiv.org/abs/2604.18934
