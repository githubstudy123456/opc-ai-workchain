# 工具栈与选型

## 选型原则

- 先低代码，后代码。
- 先跑通流程，后优化成本。
- 先保证客户数据安全，后追求方便。
- 先有人工审核，再开放自动执行。
- 能用一个工具解决的，不要拆成五个工具。

## 自动化编排工具

### Zapier

适合非技术用户和海外 SaaS 工具链。优势是集成多、上手快、AI 步骤丰富。缺点是成本可能随任务量增长，复杂逻辑不如自建灵活。

适合：

- 表单到 CRM
- 邮件自动回复
- 内容发布提醒
- AI 摘要和分类
- 海外工具联动

### Make

适合可视化流程、复杂分支和较高性价比场景。对非技术用户仍需一定学习成本。

适合：

- 多步骤流程
- 条件判断
- 表格、文档、邮件联动
- 中小团队自动化

### n8n

适合愿意自托管或有一定技术能力的一人公司。优势是可控、可扩展、适合连接内部系统。缺点是需要维护服务器、权限和错误处理。

适合：

- 私有化部署
- 客户数据敏感
- API 集成
- 长期托管服务

### 飞书 / 企业微信 / 钉钉生态

适合中国客户和组织协作场景。优势是客户熟悉、消息触达强、表格和审批可结合。缺点是跨海外 SaaS 集成不如 Zapier 丰富。

适合：

- 本地企业客户
- 内部审批
- 消息提醒
- 多维表格看板

## AI 模型与接口

### ChatGPT / OpenAI API

适合通用文本、结构化输出、工具调用、文件检索、代码辅助和多步骤任务。OpenAI Responses API 支持文本和图像输入、结构化输出、函数调用、文件搜索、网页搜索等能力，适合做业务系统里的 AI 节点。

### Claude / Gemini / 其他模型

适合长文处理、写作、研究、代码、表格和多模态任务。不同模型能力、价格、地区可用性和数据政策不同，应根据客户数据风险和成本选择。

### 本地模型

适合隐私敏感、成本可控或离线场景。缺点是部署、推理速度、效果和维护成本更高。

## 一人公司推荐组合

### 国内客户轻量版

- 飞书多维表格
- 飞书文档
- 企业微信或微信
- ChatGPT / 通义 / Kimi / DeepSeek 等模型
- 手工审核 + 固定交付模板

### 海外工具版

- Tally / Typeform
- Airtable
- Zapier 或 Make
- OpenAI API
- Notion / Google Drive
- Stripe / PayPal

### 技术服务版

- Next.js 或低代码前端
- Supabase / PostgreSQL
- n8n
- OpenAI API
- GitHub
- Vercel / Cloudflare

## 成本控制

- 为每个客户单独记录 API、自动化任务、存储和人工时间。
- AI 初稿不要无限重试，设置最大生成次数。
- 大批量任务用批处理或低成本模型。
- 高频固定任务用模板和规则，不要全部交给大模型。
- 每月复盘工具订阅，删除不用的服务。

## 安全设置

- API Key 放在环境变量或密钥管理工具。
- 给客户共享文件夹时只开放必要权限。
- 自动化流程中不要把客户隐私发到不必要的第三方工具。
- 给每条工作链设置错误通知。
- 定期导出备份。
