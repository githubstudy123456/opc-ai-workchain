# AI 自动驾驶工作流详细步骤

目标：把人从重复执行中抽离出来，让 AI 和自动化系统尽可能完成获客、筛选、沟通、报价、生产、质检、交付、复盘和复购。人只负责策略、规则、审批、异常和最终责任。

## 总原则

不要追求一开始 100% 自动化。正确顺序是：

```text
人工跑通
  -> 模板化
  -> 半自动
  -> 自动执行
  -> 异常才找人
  -> 数据驱动优化
```

一人公司的最终目标不是“完全没人管”，而是把人从每天琐碎执行中抽离成 4 个角色：

- 规则制定者：定义什么能做、什么不能做。
- 审批者：只审批高风险动作。
- 异常处理者：只处理系统无法判断的情况。
- 经营决策者：看数据、改产品、定价格、找新机会。

## 自动化等级

| 等级 | 状态 | 人的角色 | 示例 |
| --- | --- | --- | --- |
| L0 | 全人工 | 人做所有事 | 手动回复客户、手动写方案 |
| L1 | 模板化 | 人套模板 | 报价模板、邮件模板 |
| L2 | AI 辅助 | 人发指令，AI 产出 | AI 写初稿，人复制粘贴 |
| L3 | 自动编排 | 系统触发 AI，人审核 | 表单进来后自动分类和写回复 |
| L4 | 异常介入 | 系统自动执行，异常找人 | 普通线索自动跟进，高风险线索提醒 |
| L5 | 自优化 | 系统基于数据优化规则 | 根据成交率自动调整线索评分 |

建议一人公司先做到 L3，再逐步把低风险流程推到 L4。

## 总体自动驾驶架构

```text
外部触发
  -> 数据进入统一入口
  -> AI 分类与评分
  -> 规则引擎判断下一步
  -> 自动执行低风险动作
  -> 高风险动作进入审批队列
  -> 执行结果写入数据库
  -> AI 生成复盘和下一步建议
  -> 人只看异常、审批和经营看板
```

## 第 0 步：先定义“人必须保留”的动作

自动化前先列黑名单。以下动作不要让 AI 全自动完成：

- 自动签合同。
- 自动承诺收益、疗效、法律结果、税务结论。
- 自动删除客户数据。
- 自动退款、赔付或改价格。
- 自动发布高风险广告。
- 自动使用客户隐私数据做公开案例。
- 自动给法律、医疗、金融、税务最终建议。

这些动作可以让 AI 准备草稿，但必须人工确认。

## 第 1 步：把业务拆成事件

不要按“我要做一个系统”开始，要按事件拆。

### 常见事件

| 事件 | 触发条件 | 下一步 |
| --- | --- | --- |
| 新线索进入 | 表单提交、私信、邮件 | 分类、评分、回复 |
| 客户预约 | 客户选择时间 | 创建日程、提醒、准备问题 |
| 会议结束 | 录音或纪要生成 | 提取需求、生成方案 |
| 报价确认 | 客户同意范围 | 生成合同、收款提醒 |
| 项目启动 | 收到首款 | 创建项目、任务、文件夹 |
| 客户上传资料 | 文件进入文件夹 | 摘要、分类、检查缺失 |
| 初稿完成 | AI 生成内容 | 质检、修改、交付 |
| 客户反馈 | 表单或消息进入 | 分类、修订、升级 |
| 项目完成 | 验收通过 | 归档、复盘、复购 |

### 输出物

把这些事件写成一张表：

| 事件 | 输入 | AI 处理 | 自动动作 | 人工介入条件 | 输出 |
| --- | --- | --- | --- | --- | --- |

这是整个自动驾驶系统的蓝图。

## 第 3 步：设置 AI 角色分工

不要让一个 AI 助手什么都做。拆成多个角色，每个角色只负责一个环节。

### 推荐 AI 角色

| 角色 | 负责 | 输出 |
| --- | --- | --- |
| 线索分级员 | 判断客户价值和需求类型 | 优先级、跟进问题 |
| 销售助理 | 写首次回复、跟进消息 | 消息草稿 |
| 需求分析师 | 从访谈中提取需求 | 需求文档 |
| 方案顾问 | 生成方案结构和报价草案 | 方案初稿 |
| 项目经理 | 拆任务、排时间、催资料 | 任务清单 |
| 生产助理 | 生成内容、报表、配置说明 | 初稿 |
| 质检员 | 查遗漏、风险、格式 | 检查报告 |
| 复盘员 | 总结结果和可复用资产 | 复盘报告 |

### 每个 AI 角色必须有固定输入输出

示例：线索分级员

```text
输入：
- 客户行业
- 需求描述
- 预算范围
- 上线时间
- 来源渠道

输出 JSON：
{
  "need_type": "",
  "priority": "high|medium|low",
  "budget_level": "high|medium|low|unknown",
  "risk_level": "high|medium|low",
  "next_action": "",
  "human_required": true
}
```

## 第 4 步：设置规则引擎

AI 负责判断，规则负责执行。不要只靠 AI 自由发挥。

### 规则示例：线索处理

```text
如果 priority = high 且 risk_level = low：
  自动发送预约链接
  自动提醒负责人
  自动创建跟进任务

如果 priority = medium：
  自动发送资料包
  24 小时后自动跟进

如果 risk_level = high：
  不自动回复具体承诺
  推送给人工审核

如果 budget_level = unknown：
  自动询问预算和上线时间
```

### 规则示例：内容发布

```text
如果内容类型 = 普通知识分享 且质检通过：
  进入待发布队列

如果包含价格、承诺、政策、医疗、金融、法律：
  必须人工审批

如果缺少来源：
  返回修改，不进入发布
```

## 第 5 步：搭建第一条自动驾驶线：获客到预约

这是最容易产生收入的第一条线。

### 目标

客户提交需求后，系统自动完成：

- 入库
- 分类
- 评分
- 回复
- 预约
- 创建跟进任务

### 工具组合

国内轻量版：

- 飞书表单
- 飞书多维表格
- 飞书自动化
- AI 模型
- 企业微信或飞书消息

海外版：

- Tally / Typeform
- Airtable
- Zapier / Make
- OpenAI API
- Gmail / Slack / Calendly

### 详细步骤

1. 建一个需求表单  
   字段：姓名、联系方式、行业、需求、预算、希望上线时间、当前工具。

2. 表单连接线索表  
   每次提交自动创建一条线索，状态默认为“新线索”。

3. 增加 AI 分类字段  
   让 AI 根据需求生成：需求类型、优先级、风险等级、建议下一步。

4. 写入规则  
   高优先级低风险线索，自动发送预约链接；中优先级线索，自动发送案例资料；高风险线索，提醒人工审核。

5. 自动生成首次回复  
   根据客户行业和需求，生成一段简短回复。

6. 自动创建任务  
   任务包括：跟进客户、准备诊断问题、检查客户资料。

7. 设置超时提醒  
   24 小时未跟进，提醒自己；48 小时无回复，系统自动发送二次跟进。

8. 每天生成线索日报  
   包括新增线索、优先级分布、高价值线索、未跟进线索。

### 首次回复模板

```text
你好，已收到你的需求。根据你填写的信息，你主要想解决的是【AI识别的需求类型】。

我建议先做一个 15 分钟诊断，确认：
1. 当前流程怎么跑
2. 哪些步骤能自动化
3. 哪些步骤必须人工审核
4. 最小版本几天能上线

你可以直接选择一个方便的时间：{{预约链接}}
```

### 人工只需要做什么

- 看高风险线索。
- 参加诊断电话。
- 修改关键报价。
- 决定是否接单。

## 第 6 步：搭建第二条自动驾驶线：会议到报价

### 目标

会议结束后，系统自动把录音或纪要变成需求文档、方案草案、报价草案和项目任务。

### 详细步骤

1. 会议录音或实时纪要  
   使用飞书妙记、Zoom 转录、腾讯会议纪要或其他转录工具。

2. 自动保存到客户文件夹  
   文件名统一：`客户名-日期-诊断会议纪要`。

3. AI 提取需求  
   输出：客户背景、当前流程、痛点、目标、数据来源、风险、预算、时间线。

4. AI 生成流程图  
   输出当前流程和改造后流程。

5. AI 生成报价草案  
   包含范围、交付物、周期、客户配合事项、价格建议、不包含内容。

6. 规则判断是否需要人工审批  
   如果金额超过阈值、涉及高风险行业、客户要求结果承诺，必须人工审批。

7. 自动创建项目草案  
   在项目表创建记录，但状态为“待确认”。

8. 自动生成客户邮件草稿  
   人工确认后发送。

### 需求提取提示词

```text
你是 AI 自动化项目的需求分析师。请从会议纪要中提取结构化需求。

输出：
1. 客户背景
2. 当前流程
3. 主要痛点
4. 可自动化环节
5. 必须人工审核的环节
6. 数据来源
7. 风险点
8. 建议最小版本
9. 客户需要提供的资料
10. 下一步行动

会议纪要：
{{会议纪要}}
```

### 报价草案提示词

```text
你是自动化服务报价顾问。请基于需求文档生成报价草案。

要求：
- 分为诊断版、搭建版、托管版
- 写清交付物
- 写清不包含内容
- 写清客户需配合事项
- 不承诺收入增长
- 对高风险部分标注需人工确认

需求文档：
{{需求文档}}
```

### 人工只需要做什么

- 确认需求是否理解正确。
- 调整价格。
- 删除不该承诺的内容。
- 发送最终方案。

## 第 7 步：搭建第三条自动驾驶线：项目执行

### 目标

客户确认后，系统自动创建项目空间、任务、资料清单、提醒和交付检查。

### 详细步骤

1. 报价确认后，项目状态改为“已成交”。

2. 自动创建客户文件夹  
   文件夹结构：

```text
客户名/
  01-合同与报价/
  02-客户资料/
  03-流程图/
  04-自动化配置/
  05-测试记录/
  06-交付文件/
  07-复盘/
```

3. 自动创建任务列表  
   任务包括：收集资料、确认账号、画流程、搭建表格、配置自动化、测试、写说明、交付。

4. 自动发送资料清单给客户  
   要求客户提供账号、示例数据、流程说明、品牌资料、审核人。

5. 客户上传资料后自动摘要  
   AI 给每份资料生成摘要、用途、是否缺少关键信息。

6. 每天自动检查阻塞  
   如果某任务超过 24 小时未推进，提醒自己或客户。

7. 每个里程碑自动生成进度报告  
   发给客户：已完成、待确认、需要客户提供。

8. 交付前自动质检  
   检查流程是否闭环、权限是否正确、错误通知是否设置、文档是否完整。

### 项目经理提示词

```text
你是项目经理。请根据项目需求，把工作拆成任务。

输出表格字段：
- 任务名
- 负责人：我 / 客户 / 系统
- 前置条件
- 截止时间
- 验收标准
- 风险

项目需求：
{{需求文档}}
```

### 质检提示词

```text
你是自动化项目质检员。请检查这个项目是否可以交付。

检查项：
1. 输入是否明确
2. 输出是否明确
3. 是否有人工审核点
4. 是否有错误通知
5. 是否有权限说明
6. 是否有测试记录
7. 是否有操作文档
8. 是否存在合规风险
9. 是否满足报价范围

项目资料：
{{项目说明}}
```

### 人工只需要做什么

- 处理客户不配合。
- 解决工具权限问题。
- 审批最终交付。
- 做关键培训。

## 第 8 步：搭建第四条自动驾驶线：交付到复购

### 目标

项目完成后，系统自动完成验收、归档、复盘、案例沉淀、复购建议。

### 详细步骤

1. 项目状态改为“待验收”。

2. 自动生成验收表  
   每个功能对应一个测试项。

3. 客户确认后自动归档  
   报价、合同、资料、测试、交付物、复盘都放入对应文件夹。

4. AI 生成项目复盘  
   包括：节省时间、客户反馈、问题、可复用模板、下次改进。

5. AI 生成案例草稿  
   默认脱敏，不出现客户真实名称和敏感数据。

6. AI 生成复购建议  
   根据项目类型推荐：维护、第二条工作链、月报、培训、知识库更新。

7. 自动设置 7 天、30 天、90 天跟进提醒。

8. 自动生成客户满意度问卷。

### 复购提示词

```text
你是客户成功经理。请根据项目结果生成复购建议。

输出：
1. 客户已经获得的成果
2. 仍然存在的问题
3. 适合推荐的下一个服务
4. 推荐理由
5. 跟进话术

要求：
- 不夸大效果
- 不制造焦虑
- 基于项目事实

项目复盘：
{{复盘内容}}
```

### 人工只需要做什么

- 确认案例是否可公开。
- 参加重要客户复盘会。
- 决定是否给优惠或升级方案。

## 第 9 步：设置异常队列

自动驾驶系统最重要的不是“全自动”，而是“异常集中处理”。

### 异常类型

| 异常 | 触发条件 | 处理 |
| --- | --- | --- |
| 高风险行业 | 法律、医疗、金融、税务等 | 人工审核 |
| 高金额报价 | 超过设定阈值 | 人工审批 |
| 客户投诉 | 出现投诉、退款、赔偿 | 人工处理 |
| AI 不确定 | 置信度低或资料不足 | 补充资料 |
| 自动化失败 | API 报错、权限失效 | 技术处理 |
| 数据异常 | 指标突变、缺失、重复 | 人工确认 |

### 异常处理表字段

| 字段 | 示例 |
| --- | --- |
| 异常 ID | E-2026-001 |
| 来源流程 | 线索跟进 |
| 异常类型 | 高风险行业 |
| 触发原因 | 客户要求法律结论 |
| 优先级 | 高 |
| 负责人 | 我 |
| 状态 | 待处理 |
| 处理结果 | 已拒绝自动回复，转人工 |

## 第 10 步：经营看板

人抽离后，不能每天盯流程，要看经营指标。

### 每日看板

- 新增线索数
- 高优先级线索数
- 未跟进线索
- 自动化失败次数
- 待审批事项

### 每周看板

- 线索来源转化率
- 诊断预约数
- 报价数
- 成交数
- 项目交付进度
- 客户满意度
- 本周节省人工时间

### 每月看板

- 收入
- 毛利
- 复购率
- 客单价
- 工具成本
- AI 成本
- 人工介入次数
- 可复用资产数量

## 第 11 步：把人工介入率降下来

每周复盘一个指标：人工介入率。

```text
人工介入率 = 需要人工处理的任务数 / 总任务数
```

### 降低方法

- 高频问题写进 FAQ。
- 高频修改做成模板。
- 高频异常写成规则。
- 高频客户问题做成自动回复。
- 高频交付做成固定流程。
- 高频质检项做成检查清单。

### 目标

| 阶段 | 人工介入率 |
| --- | --- |
| 第 1 个月 | 70% 以下 |
| 第 2 个月 | 50% 以下 |
| 第 3 个月 | 30% 以下 |
| 成熟后 | 20% 以下 |

## 具体落地示例：一人公司 AI 自动化顾问业务

### 第 1 天：准备基础系统

- 建客户表。
- 建线索表。
- 建项目表。
- 建异常表。
- 建表单。
- 建客户文件夹模板。

### 第 2 天：搭获客自动化

- 表单提交自动进入线索表。
- AI 自动分类需求。
- AI 自动评分。
- 高价值线索推送提醒。
- 普通线索自动回复资料包。

### 第 3 天：搭诊断自动化

- 预约后自动发会议链接。
- 会议前自动生成诊断问题。
- 会议纪要自动保存。
- AI 自动提取需求。

### 第 4 天：搭报价自动化

- AI 生成方案草案。
- AI 生成三档报价。
- 规则判断是否需要人工审批。
- 人工确认后发送客户。

### 第 5 天：搭项目执行自动化

- 成交后自动创建项目空间。
- 自动生成任务。
- 自动发送资料清单。
- 自动提醒客户补资料。

### 第 6 天：搭交付质检自动化

- AI 检查交付物。
- 自动生成验收表。
- 自动生成操作说明初稿。
- 人工审批后交付。

### 第 7 天：搭复盘复购自动化

- 自动生成复盘表。
- 自动生成案例草稿。
- 自动生成复购建议。
- 自动设置 30 天跟进提醒。

## 最小可执行版本

如果只想最快上线，先做这 5 个自动化：

1. 表单进线索表。
2. AI 给线索分类和评分。
3. 高价值线索自动提醒。
4. 会议纪要自动生成需求文档。
5. 项目结束自动生成复盘和复购建议。

这 5 个做好，一人公司就能明显减少重复劳动。

## 最终工作状态

理想状态下，你每天只看 3 个地方：

- 待审批队列：哪些事情需要你点头。
- 异常队列：哪些事情系统处理不了。
- 经营看板：今天有没有线索、成交、交付和风险。

其他重复执行尽量交给 AI 和自动化系统。
