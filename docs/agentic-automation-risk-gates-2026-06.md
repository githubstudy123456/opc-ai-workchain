# 一人公司 Agent 自动化安全上线门禁（2026-06）

> 适用对象：一人公司、自由职业服务商、小微企业自动化顾问。目标是在不增加固定人手的前提下，把 AI agent、低代码/无代码自动化和人工审批组合成可交付、可计费、可审计的工作链。
>
> 检索日期：2026-06-13。避免误解：本文的 OPC 指 One-Person Company / 一人公司，不涉及 OPC UA 或 OPC Classic。

## 1. 结论

2026 年的一人公司自动化交付，不应把“agent 能调用工具”直接等同于“可以无人值守上线”。更稳的产品化路径是：

1. 先售卖固定边界的业务结果，例如“线索入库与跟进包”“会议纪要到报价单包”“客服工单分流包”。
2. 用 Zapier MCP、Make AI Agents 或 OpenAI Agents SDK 接入工具，但只开放白名单动作。
3. 在报价、付款、合同、发票、删改客户数据、对外承诺等节点强制人工审批。
4. 每个交付包都保留运行日志、输入输出样本、失败重试记录和客户验收清单。

## 2. 工具能力与适用边界

| 工具/平台 | 适合一人公司的用法 | 上线前限制 | 主要来源 |
| --- | --- | --- | --- |
| OpenAI Agents SDK / Responses API tools | 自建产品或客户私有部署；需要代码控制、工具执行、状态、审批和观测时使用 | 先做单 agent，再扩展 handoff；高风险动作接 guardrails / human review；用 traces 和 evals 复盘 | [OpenAI Agents SDK](https://developers.openai.com/api/docs/guides/agents)、[OpenAI tools](https://developers.openai.com/api/docs/guides/tools) |
| Zapier MCP | 给现有 AI 工具接 Gmail、Slack、Salesforce、表格等 SaaS；适合快速验证和轻量代运营 | 只授权必要 app/action；对“发送、更新、删除、付款”动作要求审批；检查 History | [Zapier MCP](https://zapier.com/mcp) |
| Make AI Agents | 可视化编排跨 3000+ app 的 agent 工作流；适合客户希望能看懂流程和成本时 | 每个 agent 输出结构化 JSON；失败分支进入人工队列；按场景复用模板 | [Make AI Agents](https://www.make.com/en/ai-agents) |

## 3. 六类上线门禁

| 门禁 | 必问问题 | 通过标准 | 不通过处理 |
| --- | --- | --- | --- |
| 身份与权限 | agent 以谁的身份调用工具？能读写哪些系统？ | 每个连接有 owner、用途、权限范围、撤销路径 | 降权为只读；拆分管理员连接和执行连接 |
| 输入可信度 | 输入来自客户、网页、邮件还是内部系统？可能包含提示注入吗？ | 外部输入只作为 data，不直接拼入系统指令；关键字段做 schema 校验 | 进入人工复核；记录恶意样本 |
| 工具白名单 | agent 可以执行哪些动作？ | 动作按 read / draft / send / update / delete 分级 | 对 send/update/delete 加审批或禁用 |
| 财务与合同 | 是否会影响报价、付款、发票、合同承诺？ | agent 只能生成草稿；真人确认后才发出 | 自动任务停止，转人工 |
| 记忆与状态 | 是否会写入长期记忆、CRM、客户档案？ | 写入前保存 diff；敏感字段脱敏；可回滚 | 禁止自动写入长期记忆 |
| 观测与验收 | 出错后能否定位？客户如何确认交付？ | 每次运行有 trace/log、输入、输出、工具调用、审批人、耗时 | 未记录视为未交付，不计入 SLA |

## 4. 标准交付 SOP：线索到报价自动化包

### 4.1 输入

| 输入 | 示例 | 校验 |
| --- | --- | --- |
| 线索来源 | 表单、官网聊天、邮箱、私信、CRM 新建记录 | 必须有来源 URL 或消息 ID |
| 客户信息 | 姓名、公司、行业、邮箱、需求、预算、截止时间 | 邮箱格式、预算区间、需求长度 |
| 历史资料 | 往来邮件、会议纪要、CRM 备注 | 只读，不允许 agent 直接覆盖 |

### 4.2 流程

1. 触发：新表单/新邮件/新 CRM 线索进入 `lead_intake` 队列。
2. 清洗：agent 提取行业、痛点、预算、紧急度、可交付范围，输出结构化 JSON。
3. 分级：规则优先，AI 辅助。预算高、时限近、需求明确的线索进入 `A`；信息不全进入 `NeedInfo`。
4. 草拟回复：agent 生成两版邮件：补充信息版和初步报价版。
5. 人工审批：一人公司负责人检查报价、承诺、交付日期和合同条款。
6. 执行：审批后由自动化平台发送邮件、更新 CRM、创建跟进任务。
7. 复盘：每周统计转化率、平均响应时间、需要人工修改的字段。

### 4.3 Agent 提示词模板

```text
你是“一人公司销售运营助理”。你的任务是把线索整理成可审阅的销售草稿，不得直接承诺价格、交付日期或法律/税务结论。

输入：
- lead_source: {{来源}}
- raw_message: {{客户原文}}
- crm_context: {{只读 CRM 摘要}}
- offer_catalog: {{可售卖服务包}}

输出 JSON：
{
  "lead_summary": "50 字以内摘要",
  "pain_points": ["痛点1", "痛点2"],
  "fit_score": 1-5,
  "missing_info": ["缺失信息"],
  "recommended_offer": "服务包名称或 null",
  "risk_flags": ["价格承诺/合规/数据权限/交付不确定性"],
  "draft_reply": "邮件草稿",
  "requires_human_approval": true
}

硬性规则：
1. 不得代表负责人发送消息。
2. 不得编造客户预算、案例、资质或成功率。
3. 出现合同、发票、税务、个人敏感信息、付款、删除数据时，risk_flags 必须标记。
```

### 4.4 工具配置建议

| 步骤 | Zapier MCP / Make 配置 | OpenAI SDK 配置 | 人工点 |
| --- | --- | --- | --- |
| 读取线索 | Gmail/Forms/CRM read | file_search 或业务 API read tool | 无 |
| 生成摘要 | AI action 输出 JSON | structured output | 无 |
| 写 CRM 草稿 | create draft note，不覆盖原字段 | function tool: `create_crm_note_draft` | 无 |
| 发送回复 | Gmail send 禁止自动执行 | function tool: `send_email` 需 approval | 必须审批 |
| 报价/合同 | 只创建报价草稿 | function tool: `create_quote_draft` | 必须审批 |

## 5. 异常处理

| 异常 | 检测方式 | 处理 |
| --- | --- | --- |
| 客户邮件含“忽略之前指令”等提示注入 | 规则匹配 + 模型分类 | 标记为外部不可信文本；只提取事实，不执行指令 |
| CRM 里已有冲突信息 | 同一字段多来源不一致 | 输出冲突表，暂停发送 |
| 工具调用失败 | API 返回 4xx/5xx 或超时 | 重试 2 次；仍失败则建人工任务 |
| 输出 JSON 不合法 | schema 校验失败 | 要求模型修复一次；失败进入人工 |
| 报价超出目录 | recommended_offer 为 null 或自造套餐 | 禁止发送，提示负责人更新服务目录 |
| 长期记忆写入风险 | 包含客户隐私、商业秘密、证件号 | 脱敏后写入；原文仅留在客户授权系统 |

## 6. 验收标准

| 指标 | 最低验收线 | 计费/续约含义 |
| --- | --- | --- |
| 线索响应时间 | 工作时间内 10 分钟生成可审草稿 | 可作为“响应效率提升”卖点 |
| 结构化字段准确率 | 抽样 30 条，关键字段准确率 >= 90% | 低于标准需调整提示词/规则 |
| 人工修改率 | 草稿需大改比例 <= 30% | 超过说明服务包边界太宽 |
| 高风险动作误执行 | 0 次 | 一票否决 |
| 日志完整率 | 100% 留存输入、输出、工具调用和审批记录 | 作为客户验收附件 |

## 7. 变现路径

| 产品 | 交付物 | 定价方式 | 续费理由 |
| --- | --- | --- | --- |
| 线索到报价自动化包 | 表单/邮箱/CRM 接入、线索分级、回复草稿、审批流、周报 | 一次性搭建费 + 月度维护 | 表单变化、报价目录更新、效果复盘 |
| 会议到交付任务包 | 会议纪要、行动项、工单、客户确认邮件 | 按席位或按项目 | 会议频率稳定，客户愿意买省时 |
| 客服分流与知识库包 | 工单分类、答案草稿、升级规则、知识库缺口报告 | 月费 + 工单量阶梯 | 知识库持续迭代 |
| 财务资料收集包 | 发票/合同/付款凭证清单、缺件提醒、会计交接包 | 月费 | 税期刚需，但必须人工复核 |

## 8. 合规与风险提示

- 一人有限责任公司仍要把公司财产与股东个人财产分开管理，避免人格混同风险。涉及注册资本、出资期限、公司治理和股东责任时，应以现行《公司法》和当地登记机关要求为准。
- 中国小微企业税收、增值税小规模纳税人、小型微利企业所得税优惠等政策存在期限和口径变化；自动化系统只能做资料收集和提醒，不应自动给客户出具税务结论。
- Agent 安全研究在 2026 年继续强调记忆污染、工具滥用和高风险场景缺少原生隔离的问题。对一人公司来说，最现实的控制不是追求“全自动”，而是把高风险动作拆成草稿、审批、执行、审计四步。
