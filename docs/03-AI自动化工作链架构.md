# AI 自动化工作链架构

## 总体架构

```text
客户入口
  -> 数据采集
  -> 分类与优先级
  -> AI 生成或分析
  -> 人工审核
  -> 自动交付
  -> 记录与归档
  -> 复盘与复购
```

一人公司不要一开始追求复杂系统。最小工作链应该能回答四个问题：

- 输入从哪里来？
- 中间如何处理？
- 谁负责审核？
- 输出交给谁，并如何记录？

## 层级一：信息入口

常见入口：

- 表单：客户需求、预约、售后问题。
- 邮箱：正式文件、合同、资料。
- IM：微信、企业微信、飞书、Slack。
- 平台：电商后台、CRM、广告后台、内容平台。

设计原则：

- 所有入口最终进入一个统一表。
- 必填字段尽量少，但必须包含客户、需求、截止时间、预算或优先级。
- 每条线索自动生成编号，后续合同、文件和账单都用同一编号。

## 层级二：数据底座

一人公司常用数据底座：

- 轻量：Notion、飞书多维表格、Airtable、Google Sheets。
- 技术型：PostgreSQL、Supabase、SQLite。
- 文档型：GitHub、Google Drive、飞书文档、腾讯文档。

建议表结构：

- 客户表：公司、联系人、渠道、行业、状态。
- 线索表：需求、预算、优先级、来源、下一步。
- 项目表：范围、报价、截止时间、负责人、交付状态。
- 资料表：文件、链接、权限、摘要、归属项目。
- 复盘表：结果、问题、可复用资产、下次行动。

## 层级三：AI 处理

AI 适合处理：

- 分类：线索类型、客户行业、优先级。
- 摘要：会议纪要、长文档、客户资料。
- 起草：邮件、方案、脚本、FAQ、周报。
- 转换：把访谈变成需求文档，把表格变成报告。
- 检查：格式、遗漏项、语气、风险词。

AI 不应独立处理：

- 法律、医疗、金融、税务等最终专业判断。
- 无来源的事实断言。
- 客户敏感数据的任意外发。
- 高风险广告承诺。
- 无人工审核的自动报价或自动签约。

## 层级四：人工审核点

每条商业工作链至少设置一个人工审核点：

- 报价前审核范围和责任。
- 交付前审核事实、格式、客户隐私。
- 发布前审核平台规则和广告风险。
- 收款前审核合同、发票和主体一致。

审核不是拖慢效率，而是保护一人公司的信誉和责任边界。

## 层级五：交付与归档

交付文件要标准化：

- 方案：PDF 或在线文档。
- 数据：表格或看板。
- 自动化：流程图、账号权限说明、维护说明。
- 培训：录屏、操作文档、FAQ。
- 验收：验收清单和客户确认记录。

归档规则：

- 每个客户一个文件夹。
- 每个项目一个编号。
- 合同、报价、发票、资料、交付物、沟通纪要分开存。
- 重要账号和密钥不能明文放在普通文档。

## 一条完整示例：客户线索自动跟进

```text
表单提交
  -> 写入线索表
  -> AI 判断行业、预算、紧急程度
  -> 自动发送确认邮件
  -> 高价值线索推送到手机
  -> AI 生成首次沟通提纲
  -> 人工电话/微信沟通
  -> AI 根据纪要生成报价草案
  -> 人工审核报价
  -> 发合同和收款链接
  -> 项目表自动创建任务
```

## 一条完整示例：内容生产工作链

```text
客户资料库
  -> 选题池
  -> AI 生成标题和大纲
  -> 人工选择
  -> AI 生成初稿
  -> 事实核验和品牌语气检查
  -> 多平台改写
  -> 客户确认
  -> 定时发布
  -> 数据回收
  -> 复盘报告
```

## 自动化成熟度

| 阶段 | 特征 | 重点 |
| --- | --- | --- |
| 0 | 全靠人工 | 记录流程 |
| 1 | 模板化 | 固定输入输出 |
| 2 | 半自动 | 表单、表格、提醒、初稿 |
| 3 | 自动编排 | 多工具联动，人工审核 |
| 4 | 智能运营 | 数据驱动优化和复购 |

一人公司通常做到阶段 2 或 3 就能明显提高产能，不必过早追求完全自动化。
